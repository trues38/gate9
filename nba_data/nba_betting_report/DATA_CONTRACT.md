# Data Contract - Input/Output Specification

## 1. Input JSON Contract

### 1.1 Required Structure
```
{
  "games": [array of game objects]
}
```

### 1.2 Required Fields per Game Object
- `game_id` (string)
- `date` (string, format: YYYY-MM-DD)
- `teams` (object)
  - `home` (string)
  - `away` (string)
- `scores` (object)
  - `home` (integer)
  - `away` (integer)
- `box_stats` (object)
  - `home_fg_pct` (float, 0.0-1.0)
  - `away_fg_pct` (float, 0.0-1.0)
  - `home_3p_pct` (float, 0.0-1.0)
  - `away_3p_pct` (float, 0.0-1.0)
  - `home_rebounds` (integer)
  - `away_rebounds` (integer)
- `market_line` (float)

### 1.3 Optional Fields
None

### 1.4 PROHIBITED Fields
- **edge_score** (generated by Pattern Matcher)
- win_probability
- predicted_winner
- expected_value
- regime_label

### 1.5 Field Constraints
- All required fields must be present
- Null values not permitted
- Empty strings not permitted for string fields
- Negative values not permitted for scores and rebounds

---

## 2. edge_score Generation Contract

### 2.1 Responsible Component
**Pattern Matcher** (`agents/pattern_matcher.py`)

### 2.2 Generation Rules
- Calculated from box_stats and scores only
- market_line MUST NOT be used in calculation
- Output range: 0-100 (float, rounded to integer)
- Deterministic: same input → same edge_score

### 2.3 Inputs Used
- box_stats.home_fg_pct
- box_stats.away_fg_pct
- box_stats.home_3p_pct
- box_stats.away_3p_pct
- box_stats.home_rebounds
- box_stats.away_rebounds
- scores.home
- scores.away

### 2.4 Inputs NOT Used
- market_line
- game_id
- date
- teams

### 2.5 Output Location
`game_patterns[i].edge_score`

---

## 3. market_line Usage Contract

### 3.1 First Usage Point
**Decision Layer** (`agents/market_decision.py`)

### 3.2 Prohibited Usage Points
- Structural Analyst (pass-through only)
- Pattern Matcher (MUST NOT use for edge_score)
- Report Editor (display only, no analysis)

### 3.3 Permitted Operations
- Read market_line value
- Compare with edge_score
- Generate line_comment (structural-market relationship)

### 3.4 Prohibited Operations
- Modify edge_score based on market_line
- Calculate win probability from market_line
- Use market_line for pattern matching
- Include market_line in edge_score calculation

---

## 4. Output Contract (Daily_Report.md)

### 4.1 Required Sections (Fixed Order)
1. Executive Summary
2. Betting Decisions
   - High Confidence
   - Monitor
   - Pass
3. Pattern Analysis
4. Risk Factors
5. Data Quality

### 4.2 Required Content per Section

**Executive Summary:**
- Total Games Analyzed
- Bet Signals
- High Confidence Bets

**Betting Decisions:**
- Game ID
- Action (BET/MONITOR/PASS)
- Side (home/away)
- Reasoning
- Line comment
- Risks

**Pattern Analysis:**
- Game ID
- Structural profile descriptors
- Historical pattern descriptors

**Risk Factors:**
- List of structural risks

**Data Quality:**
- Valid game count
- Total game count
- Anomalies (if any)

### 4.3 PROHIBITED Content
- Win probability
- Win rate
- Outcome predictions ("Team X will win")
- Expected value (EV)
- Betting recommendations ("You should bet")
- Performance metrics (ROI, profit/loss)
- Statistical confidence intervals
- Probability percentages

### 4.4 REQUIRED Terminology
- "BET" = actionable structural regime detected
- "MONITOR" = weak signal, observation required
- "PASS" = insufficient structural signal
- edge_score displayed as "score: X" only
- No probability language

## 5. Pipeline Data Flow Contract

### 5.1 Stage 1: Structural Analyst
**Input:** Raw JSON
**Output:** game_contexts
**Modifications:** None (normalization only)
**Prohibited:** edge_score generation, market_line analysis

### 5.2 Stage 2: Pattern Matcher
**Input:** game_contexts
**Output:** game_patterns (includes edge_score)
**Modifications:** Calculates edge_score
**Prohibited:** market_line usage

### 5.3 Stage 3: Decision Layer
**Input:** game_patterns (with edge_score)
**Output:** betting_decisions
**Modifications:** Adds action, confidence, line_comment
**Prohibited:** edge_score recalculation

### 5.4 Stage 4: Report Editor
**Input:** All previous outputs
**Output:** Daily_Report.md (markdown string)
**Modifications:** None (formatting only)
**Prohibited:** New calculations, interpretations

### 5.5 Regime Logger (Passive)
**Input:** All pipeline outputs
**Output:** regime_observations.jsonl (append)
**Modifications:** None
**Prohibited:** Influencing pipeline decisions

## 6. Contract Violation Consequences

### 6.1 edge_score in Input JSON
- Pattern Matcher calculation bypassed
- Market-independence principle violated
- Reproducibility compromised
- Pipeline version tracking broken
- SKILL.md specification violated

### 6.2 market_line Used in Pattern Matcher
- Market-independence principle violated
- edge_score no longer purely structural
- Transparency compromised
- SKILL.md specification violated
- System philosophy broken

### 6.3 edge_score Recalculated in Decision Layer
- Decision Layer role violated
- Determinism broken
- edge_score inconsistency between stages
- Pipeline contract violated

### 6.4 Win Probability in Output
- SKILL.md prohibition violated
- System positioned as predictor (not classifier)
- User misinterpretation risk
- Legal/regulatory risk
- System philosophy violated

### 6.5 Regime Log Used for Decisions
- v0.1 specification violated
- Post-hoc analysis principle violated
- Minimum observation requirement bypassed
- Regime detection premature

### 6.6 Missing Required Input Fields
- Pipeline execution failure
- Structural Analyst validation failure
- Data Quality section reports anomaly
- edge_score calculation may use defaults

### 6.7 Report Template Modified
- Output contract violated
- Stability guarantee broken
- User expectation violated
- "Sellable product" contract broken

## 8. Data Type Contract

### 8.1 Input Types
- game_id: string (non-empty)
- date: string (ISO format YYYY-MM-DD)
- team codes: string (2-3 uppercase letters)
- scores: integer (≥0)
- percentages: float (0.0-1.0)
- rebounds: integer (≥0)
- market_line: float (any value)

### 8.2 Intermediate Types
- edge_score: float (0.0-100.0, rounded to integer)
- action: enum ["bet", "monitor", "pass"]
- confidence: enum ["high", "medium", "low"]
- line_comment: string (Korean/English)

### 8.3 Output Types
- Daily_Report.md: UTF-8 markdown text
- regime_observations.jsonl: UTF-8 JSON Lines

---

## 9. Integrity Constraints

### 9.1 Input Integrity
- One game_id per observation
- Unique game_id within single execution
- Valid date format
- Non-negative numeric values where applicable

### 9.2 Pipeline Integrity
- edge_score calculated exactly once (in Pattern Matcher)
- market_line read-only until Decision Layer
- No data loss between stages
- All games in input appear in output

### 9.3 Output Integrity
- All 5 sections present in report
- Section order preserved
- No prohibited terminology
- Valid markdown syntax

### 9.4 Log Integrity
- Append-only regime_observations.jsonl
- One line per game per execution
- Valid JSON per line
- pipeline_version tag present
